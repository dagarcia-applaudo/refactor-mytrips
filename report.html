Cómo leer los números. "1 developer" es la suma PERT de todas las tareas (esfuerzo = duración). "N developers" es la duración calendario: makespan de un reparto real de tareas (§5), más code review repartido (12 h / N), más dos ciclos de soporte a QA repartibles entre 2 devs como máximo, todo multiplicado por (1 + 8 % × (N − 1)). El esfuerzo total en horas-dev crece con N (§6).

6. Escenarios de staffing

Modelo. Duración(N) = [makespan de desarrollo con N devs (list scheduling sobre el grafo, prioridad por cola más larga) + code review / N + QA1 y QA2 repartidos entre min(N, 2) devs] × (1 + 0.08 × (N − 1)).
Overhead de 8 % por dev adicional: ~0.5 h/día por dev de sincronización (daily técnica, acuerdo de contratos, review cruzado), que es ≈ 7 % de 7.04 h, más la resolución de conflictos en archivos hotspot compartidos (MyTripsHomeMiddleware.kt, MyTripsHomeReducer.kt, VolarisDataBase.kt, BookingCardPagedHelper.kt). Es lineal porque cada dev nuevo agrega canales de integración sobre los mismos archivos.
